## 개요

**R.A.M.P (Random Amazing Magic Party)** 는 4명이 3인칭으로 싸우는 파티 난투 게임입니다. 상대를 죽이는 대신 기절 수치를 채워 기절시키고, 기절한 상대를 지팡이로 쳐서 날려 보냅니다. 네 번 날아가면 장외. 3라운드 동안 라운드마다 맵과 승리 조건이 바뀝니다.

연구에 지친 "힘법사"들이 휴가지로 떠난다는 설정이고, 첫 스테이지는 워터파크입니다. 팀원 다섯 명이 모두 기획자여서, 각자 기획한 영역을 Unity로 직접 구현했습니다.

## UI 설계 원칙

- **안내는 공간과 사물로**: 화면 위 안내는 적당하면 괜찮지만, 많아지면 난잡해지고 몰입이 떨어집니다. 그래서 공간과 사물이 다음 행동을 알려 주게 설계했습니다.
- **0.1초 안에 읽히게**: 즉각 반응해야 하고, 어려운 이해 없이 즐기는 게임입니다. 그래서 정보는 최대한 쉽고 간단하게 알려 주도록 했습니다.

## 맡은 역할

UI 영역의 기획서 작성부터 구현까지 혼자 맡았고, 전투·라운드 시스템은 한 명과 함께 만들었습니다.

- **UI 기획서**: 화면 목록과 각 화면의 동작·위치·문구를 정리한 UI 기획서(M1)를 쓰고, 플레이테스트 결과에 맞춰 고쳐 나갔습니다.
- **HUD**: 마법·버프 칸, 기절 게이지, 라운드별 미션 표시, 피격 테두리, 전투 점수 팝업. 난전 속에서도 "내가 때렸다, 내가 맞았다, 저 사람은 지금 날릴 수 있다"가 바로 읽히는 것을 기준으로 삼았습니다.
- **흐름 화면**: 타이틀(로고를 방망이로 치는 연출), 접속, 로딩(휴가 컷신과 팁), 라운드 시작 안내, 결과 화면과 최종 시상식.
- **공통 UI 부품**: 확인 창, 열린 화면 관리(Esc·마우스 잠금 처리), 번역 표 기반 글자 표시, 설정 화면(그래픽·사운드·감도), ESC 메뉴.
- **의상실**: 캐릭터 외형과 무기를 고르는 꾸미기 화면과, 그 공간으로 들어가는 연출.
- **유리 UI 개편**: 뒤 화면을 흐리게 비추는 셰이더를 만들어 HUD 칸 전체에 적용했습니다.

## 일하는 방식

- 기획서를 개발 기준으로 두고, 기획서에 없는 수치나 동작은 임의로 정하지 않고 팀에 확인했습니다.
- 다른 영역이 쓸 UI 함수는 공개 문서(API 문서)에 이름·위치·사용법을 적어 팀원이 바로 가져다 쓰게 했습니다.
- Jira 이슈 단위로 브랜치를 나누고, Confluence에 작업 기록을 남겼습니다.
- Claude와 Unity MCP를 활용해 구현 속도를 높이고, 기획자 팀이 코드를 함께 다룰 수 있는 작업 규칙을 만들었습니다.

## 배운 점

- HUD는 정보를 다 보여 주는 곳이 아니었습니다. 기절·차지 같은 상태는 캐릭터 애니메이션과 이펙트로 나눠 보여 주고, 늘 보이는 정보는 최소로 줄였을 때 플레이테스트 반응이 가장 좋았습니다.
- 여러 화면이 동시에 열릴 수 있는 게임에서는 Esc와 마우스 잠금을 화면마다 처리하면 반드시 꼬입니다. 열린 화면을 한 곳에서 세는 구조로 바꾼 뒤 관련 버그가 사라졌습니다.

> 플레이 영상과 스크린샷은 추가 예정입니다.
